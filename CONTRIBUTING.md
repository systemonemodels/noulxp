# Contributing to OpenDXP

OpenDXP is a standard first and code second. A change to what a package means
is a change to SPEC.md, the schemas and the reference runtime together.

## What is most useful

- **A model the profiles cannot describe.** Open an issue with the model, the
  exact input construction of its own code, and what `template.json` or
  `prompt.json` would need. This is how the standard grows.
- **A converter** for another model family (Von, open-jev, Kev, Nimble, ...):
  `src/opendxp/export/<family>.py`, a native adapter in `src/opendxp/native/`
  that runs the model's own code, and the validation results.
- **Another engine.** The standard is language-neutral. An engine in Rust,
  Go or JavaScript that passes the conformance files of the published
  packages is the strongest test of the spec; report where SPEC.md was
  ambiguous.
- **Backend results**: `opendxp check --device <backend>` on hardware we do not
  have (CUDA, OpenVINO, QNN, DirectML, ROCm), with the report JSON.

## Rules for changes

1. **Normative changes** (anything in SPEC.md that uses MUST, SHOULD or MAY,
   the schemas, `src/opendxp/spec.py`) need an issue first, and bump the
   standard's version when they change what an existing package means.
2. **Conformance files are generated by the model's own code**, never by the
   reference runtime, and record which code and versions produced them. A
   converter that needed model-specific logic in the runtime to pass has not
   passed: move that logic into the declarative files or propose a spec change.
3. **No invented numbers.** VALIDATION.md and the paper report only what a
   report file in the repository or the packages supports.
4. **Nothing in a package executes.** No templates with logic, no pickles, no
   `trust_remote_code`.

## Development

```bash
python -m venv .venv && . .venv/bin/activate
pip install -e ".[dev,onnx]"
pytest                      # no downloads; a tokenizer is built in memory
ruff check src tests scripts && ruff format --check src tests scripts
```

The request set lives in `scripts/build_requests.py`; run it to regenerate
`src/opendxp/data/requests-0.1.jsonl`. Changing it changes the standard's
conformance set: packages then need their conformance files regenerated.

Commits: one logical change each, with a message that says what changed and
why. Sign-off is not required. By contributing you agree that your
contribution is licensed under Apache-2.0.
